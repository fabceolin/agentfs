### User Story

**As a** developer
**I want** to query the filesystem at any point in time
**So that** I have audit trail and data recovery capabilities

### Core Implementation Components

1. **`DuckAgentFSSnapshot`** - Read-only snapshot struct implementing `FileSystem` trait
2. **`snapshot_at(event_id)`** - Create snapshot at specific event
3. **`current_event_id()`** - Get latest event ID
4. **`list_events(limit, offset)`** - Paginated event timeline
5. **`diff(from_event, to_event)`** - Compare two snapshots
6. **Historical CTE Query** - Window function for temporal reconstruction

## Implementation Gaps & Technical Debt

### Bug in Story Test Code

**Location**: Story test "Test 3: Diff" (lines 339-356)

**Issue**: Test deletes `/deleted.txt` without creating it first.

**Original (Broken)**:
```rust
let start = fs.current_event_id().await.unwrap();
// ... create new.txt, modified.txt ...
fs.remove("/deleted.txt").await.unwrap(); // FILE DOESN'T EXIST!
```

**Fixed** (in `setup_diff_timeline` above):
```rust
fs.write_file("/deleted.txt", b"will be deleted").await.unwrap();
let start = fs.current_event_id().await.unwrap();
// ... other operations ...
fs.remove("/deleted.txt").await.unwrap(); // Now file exists
```

### Security Concern: String Interpolation

**Location**: `DuckAgentFSSnapshot::query_current()` method (lines 124-158)

**Issue**: Direct string formatting with `self.event_id`:
```rust
let historical_query = format!(
    "... WHERE event_id <= {} ...",
    self.event_id,  // Direct interpolation
);
```

**Risk Level**: LOW (event_id is i64, not user string)

**Recommendation**: Refactor to parameterized query pattern for consistency.

### Technical Debt: CTE Duplication

**Issue**: `self.event_id` appears 3 times in CTE template.

**Recommendation**: Use DuckDB parameter binding or single CTE filter.

```rust
async fn test_snapshot_at_valid_event() {
```

### 1.4-INT-002: Snapshot Read File Returns Historical Content

```rust
#[tokio::test]
async fn test_snapshot_read_file_historical() {
    // Given: File modified after snapshot point
    let fs = DuckAgentFS::open(test_config()).await.unwrap();
    fs.write_file("/test.txt", b"version 1").await.unwrap();
    let event_v1 = fs.current_event_id().await.unwrap();
    fs.write_file("/test.txt", b"version 2").await.unwrap();

    // When: Snapshot at v1, read file
    let snapshot = fs.snapshot_at(event_v1).await.unwrap();
    let content = snapshot.read_file("/test.txt").await.unwrap();

    // Then: Returns v1 content
    assert_eq!(content, Some(b"version 1".to_vec()));

    // Current should have v2
    let current = fs.read_file("/test.txt").await.unwrap();
    assert_eq!(current, Some(b"version 2".to_vec()));
}
```

### 1.4-INT-006: Snapshot Shows Deleted File

```rust
#[tokio::test]
async fn test_snapshot_deleted_file() {
    // Given: File created then deleted
    let fs = DuckAgentFS::open(test_config()).await.unwrap();
    fs.write_file("/test.txt", b"content").await.unwrap();
    let event_created = fs.current_event_id().await.unwrap();
    fs.remove("/test.txt").await.unwrap();

    // Current: file does not exist
    let current = fs.read_file("/test.txt").await.unwrap();
    assert!(current.is_none());

    // When: Snapshot at creation point
```
