### Core Functionality

An append-only journal model for filesystem operations where:
- All operations are immutable events in `fs_journal`
- Current state is derived via `fs_current` view using ROW_NUMBER() window function
- Binary data stored in `fs_data` with chunking support
- Supporting structures: `kv_store`, `tool_calls`, sequences, indexes

### Key Design Principles

| Principle | Description | Test Focus |
|-----------|-------------|------------|
| **Immutability** | No UPDATEs allowed on journal table | Constraint enforcement |
| **State Derivation** | Current state computed via ROW_NUMBER() | View correctness |
| **Time-Travel** | Point-in-time recovery via event_id filtering | Temporal queries |
| **Audit Trail** | Complete history preserved for forensics | Actor/session tracking |

## Risk-Driven Test Scenarios

These scenarios address critical risks identified in the QA review.

### Risk: Concurrent Event Insertion Race Conditions

**Probability:** Medium | **Impact:** High

| ID | Level | Priority | Test | Expected Result | Justification |
|----|-------|----------|------|-----------------|---------------|
| 1.1-CONC-001 | E2E | P0 | 100 concurrent file creates from multiple sessions | All inodes unique, no sequence gaps or duplicates | Sequence atomicity |
| 1.1-CONC-002 | E2E | P1 | Concurrent updates to same inode | All events recorded chronologically, fs_current shows latest | State consistency |
| 1.1-CONC-003 | E2E | P1 | Concurrent delete and create operations | No orphaned state, fs_current accurate post-operations | Delete isolation |

**Test Implementation:**
```python
async def test_concurrent_creates():
    tasks = [create_file(get_conn(), i) for i in range(100)]
    inodes = await asyncio.gather(*tasks)
    assert len(inodes) == len(set(inodes)), "Duplicate inodes detected!"
    assert max(inodes) - min(inodes) == 99, "Sequence gaps detected!"
```

### Risk: Delete Logic Complexity in fs_current View

**Probability:** Medium | **Impact:** Medium

| ID | Level | Priority | Test | Expected Result | Justification |
|----|-------|----------|------|-----------------|---------------|
| 1.1-DEL-001 | Integration | P0 | File created, updated 5x, then deleted | File NOT in fs_current | Delete exclusion logic |
| 1.1-DEL-002 | Integration | P0 | Deleted file recreated with same name (new inode) | New file appears with new inode only | Name reuse handling |
| 1.1-DEL-003 | Integration | P1 | Delete, recreate same inode, delete again | File NOT in fs_current after final delete | Multi-delete cycles |
| 1.1-DEL-004 | Integration | P1 | Parent directory deleted with child files | All children excluded from fs_current | Cascade semantics |

**Test Implementation:**
```sql
-- 1.1-DEL-001: Create, Update 5x, Delete
INSERT INTO fs_journal (inode, event_type, parent, name, mode, size) VALUES (100, 'create', 1, 'victim.txt', 33188, 0);
INSERT INTO fs_journal (inode, event_type, parent, name, mode, size) VALUES (100, 'update', 1, 'victim.txt', 33188, 100);
-- ... (5 updates total)
INSERT INTO fs_journal (inode, event_type, parent, name, mode) VALUES (100, 'delete', 1, 'victim.txt', 33188);
SELECT COUNT(*) FROM fs_current WHERE inode = 100;
-- Expected: 0
```

### Risk: fs_current View Performance Degradation

**Probability:** High | **Impact:** High

| ID | Level | Priority | Test | Expected Result | Justification |

| 1.1-PERF-002 | E2E | P1 | Directory listing (WHERE parent = N) with 100K events | < 100ms | Index effectiveness |
| 1.1-PERF-003 | E2E | P2 | 1M events performance degradation | Linear or sub-linear growth | Scaling validation |

### Risk: Rename Operation Integrity

**Probability:** Medium | **Impact:** Medium

| ID | Level | Priority | Test | Expected Result | Justification |
|----|-------|----------|------|-----------------|---------------|

### Performance Dataset (E2E)

```sql
-- Generate 100K events for performance testing
-- Use bulk INSERT for efficiency
INSERT INTO fs_journal (inode, event_type, parent, name, mode, size)
SELECT i+1, 'create', 1, 'file_' || i || '.txt', 33188, i * 100
```
