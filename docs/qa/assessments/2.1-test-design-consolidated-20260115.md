## Critical Path Tests (P0 Summary)

### STORY-2.1.1 P0 (8 tests)
- Parse H1-H6 headers
- Parse paragraphs
- Parse ordered/unordered lists
- Parse code blocks
- Generate sequential edges

### STORY-2.1.2 P0 (7 tests)
- Extract `{{variable}}` patterns
- Infer bool/enum/number types
- Extract YAML frontmatter

### STORY-2.1.3 P0 (10 tests)
- Detect template patterns (`*-tmpl.md`)
- Check document conformance
- Normalize status variants ([Done], [**Done**], [Complete], [Dev Complete])
- Directory scanning

### STORY-2.1.4 P0 (6 tests)
- Rule-based fallback transformation
- TEA availability check
- Dry-run mode file safety

## CI Pipeline Recommendations

### Tier 1: Always Run (No External Deps)
```bash
# ~64 tests, ~5 seconds
cargo test --lib -- --skip "requires_tea" --skip "requires_model"
```

### Tier 2: Integration (With TEA, No Model)
```bash
# ~34 additional tests, ~30 seconds
TEA_BINARY=/path/to/tea cargo test -- --ignored --skip "requires_model"
```

### Tier 3: Full Suite (With TEA + Model)
```bash
# ~6 additional tests, ~2 minutes (LLM inference)
TEA_BINARY=/path/to/tea \
GGUF_MODEL_PATH=/path/to/model.gguf \
cargo test -- --ignored
```

## Risk Matrix

| Risk | Probability | Impact | Stories | Mitigation |
|------|-------------|--------|---------|------------|
| Parser crash on malformed markdown | Low | High | 2.1.1 | Edge case unit tests |
| Wrong type inference | Medium | Medium | 2.1.2 | Known variable lookup tests |
| Status normalization miss | Medium | Low | 2.1.3 | Extensive variant tests |
| TEA subprocess failure | Medium | High | 2.1.4 | Availability check + fallback |
| Dry-run writes accidentally | Low | Critical | 2.1.4 | Filesystem verification tests |

## Test Coverage Gaps

| Gap | Risk Level | Recommendation |
|-----|------------|----------------|
| Object type variables | Low | Deferred - reserved for nested YAML |
| Table parsing | Low | Not in AC - defer to enhancement |
| Concurrent directory scanning | Low | Single-threaded is sufficient |
| Model response validation | Medium | Manual QA for LLM outputs |

## Recommendations

1. **Implement tests in dependency order**: 2.1.1 -> 2.1.2 -> 2.1.3 -> 2.1.4
2. **CI pipeline**: Start with Tier 1, add Tier 2 when TEA available in CI
3. **Manual QA**: LLM-based transformations should have spot-check review
4. **Documentation**: Each test file should reference this design document
5. **Coverage tracking**: Run `cargo tarpaulin` to verify actual vs designed coverage
