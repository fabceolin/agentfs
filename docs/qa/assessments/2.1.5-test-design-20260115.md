# Test Design: STORY-2.1.5 - Cross-Document Relationships and Virtual Rendering

Date: 2026-01-15
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 40
- Unit tests: 26 (65%)
- Integration tests: 13 (32.5%)
- E2E tests: 1 (2.5%)
- Priority distribution: P0: 17, P1: 16, P2: 7

## Rationale

This is a **complex, high-risk story** with multiple integration points:
- FUSE filesystem operations (read/write interception)
- DuckDB PGQ query execution
- Tera template rendering
- Virtual file abstraction (.source suffix)

**Risk Assessment:** HIGH - This story modifies fundamental FUSE read behavior. Bugs could corrupt file reads or cause data loss.

Testing strategy focuses on:
- **Unit tests**: Template parsing, query() function, Tera features (no external deps)
- **Integration tests**: FUSE read/write behavior, .source access (requires mount)
- **E2E tests**: Complete workflow validation

### AC1: Markdown files with Tera + DuckDB PGQ queries

| ID | Level | Priority | Test | Justification |
|----|-------|----------|------|---------------|
| 2.1.5-UNIT-001 | Unit | P0 | Parse Tera syntax in markdown without error | Core parsing validation |
| 2.1.5-UNIT-002 | Unit | P0 | Detect malformed Tera syntax gracefully | Error handling |
| 2.1.5-UNIT-003 | Unit | P1 | Parse nested Tera blocks | Complex template support |
| 2.1.5-UNIT-004 | Unit | P1 | Handle escaped Tera delimiters | Edge case |

**Given-When-Then for P0 tests:**

```gherkin
# 2.1.5-UNIT-001
Given markdown content with valid Tera syntax "{% for x in items %}{{ x }}{% endfor %}"
When TemplateProcessor.render() is called
Then no parsing error should occur
And result should be empty string (no items)

# 2.1.5-UNIT-002
Given markdown content with malformed Tera "{% for x in %}"
When TemplateProcessor.render() is called
Then should return descriptive error (not panic)
And error message should indicate line number
```

**Given-When-Then for P0 tests:**

```gherkin

And file /mnt/data.json contains "{{ not_rendered }}"

Given AgentFS mounted with DuckDB containing documents

```

## Implicit Tests (Safety & Security)

### Error Handling & Safety

| ID | Level | Priority | Test | Justification |
|----|-------|----------|------|---------------|
| 2.1.5-UNIT-024 | Unit | P0 | Render error returns error comment, not crash | Safety |
| 2.1.5-UNIT-025 | Unit | P0 | SQL injection in query() is escaped/prevented | Security |
| 2.1.5-INT-019 | Integration | P0 | FUSE read error returns proper errno | FUSE compliance |
| 2.1.5-INT-020 | Integration | P1 | Infinite loop in template times out | Safety |

**Given-When-Then for P0 tests:**

```gherkin
# 2.1.5-UNIT-024
Given template with syntax error "{% for %}"
When FUSE read is attempted
Then should return content with error comment "<!-- Render error: ... -->"
And should NOT crash or return empty

# 2.1.5-UNIT-025
Given template with malicious SQL "{{ query(\"'; DROP TABLE gd_documents; --\") }}"
When rendered
Then should NOT execute DROP TABLE
And should return error about invalid query

# 2.1.5-INT-019
Given AgentFS mounted at /mnt
And render fails for /mnt/bad.md
When user runs `cat /mnt/bad.md`
Then should return non-zero exit code or error content
And errno should be appropriate (e.g., EIO)
```

## Recommended Execution Order

### CI Pipeline (No FUSE mount required):

```bash
# ~26 unit tests, ~5 seconds
cargo test --lib graphdocs::renderer -- --skip "requires_fuse"
```

1. **P0 Unit tests** - UNIT-001, 002, 005, 006, 007, 008, 014, 015, 016, 024, 025
2. **P1 Unit tests** - UNIT-003, 004, 009, 010, 011, 017-020, 026
3. **P2 Unit tests** - UNIT-012, 013, 021-023

### Full Suite (With FUSE mount):

```bash
# ~14 additional tests, ~30 seconds
AGENTFS_MOUNT=/tmp/agentfs_test cargo test -- --ignored
```

1. All CI Pipeline tests
2. **P0 Integration tests** - INT-001, 002, 003, 007, 008, 011, 013, 014, 019
3. **P0 E2E test** - E2E-001
4. **P1 Integration tests** - INT-004, 005, 006, 009, 010, 012, 015, 016, 017, 020
