# Test Design: Story 2.1.2 - Variable Detection and Typing

Date: 2026-01-15
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 24
- Unit tests: 18 (75%)
- Integration tests: 6 (25%)
- E2E tests: 0 (0%)
- Priority distribution: P0: 7, P1: 12, P2: 5

## Rationale

Variable detection and typing involves:
- Pattern matching (pure unit tests)
- Type inference logic (pure unit tests)
- YAML frontmatter parsing (unit tests with test fixtures)
- Database insertion (integration tests with test DB)

The type system affects data validation downstream, making P0 tests critical for type correctness.

## Test Scenarios by Acceptance Criteria

### AC1: Detect variables `{{name}}` with typed inference

| ID | Level | Priority | Test | Justification |
|----|-------|----------|------|---------------|
| 2.1.2-UNIT-001 | Unit | P0 | Extract `{{variable}}` from plain text | Core variable detection |
| 2.1.2-UNIT-002 | Unit | P0 | Extract multiple variables from same section | Common document pattern |
| 2.1.2-UNIT-003 | Unit | P1 | Handle variable in header content | Variables in headings |
| 2.1.2-UNIT-004 | Unit | P1 | Handle variable in code block (preserve, don't process) | Code blocks may contain template syntax |
| 2.1.2-UNIT-005 | Unit | P2 | Handle malformed variable `{{unclosed` | Edge case - shouldn't crash |
| 2.1.2-UNIT-006 | Unit | P2 | Handle nested braces `{{{var}}}` | Edge case |

**Given-When-Then for P0 tests:**

```gherkin
# 2.1.2-UNIT-001
Given content "Hello {{name}}, welcome!"
When extract_variables is called
Then result should contain "name"

# 2.1.2-UNIT-002
Given content "{{title}} by {{author}} ({{year}})"
When extract_variables is called
Then result should contain ["title", "author", "year"]
And result length should be 3
```

### AC2: Support variable types: `bool`, `enum`, `number`, `string`, `string[]`, `object`

| ID | Level | Priority | Test | Justification |
|----|-------|----------|------|---------------|
| 2.1.2-UNIT-007 | Unit | P0 | Infer bool type for known bool variables | Type safety for flags |
| 2.1.2-UNIT-008 | Unit | P0 | Infer enum type for known enum variables | Type safety for constrained choices |
| 2.1.2-UNIT-009 | Unit | P0 | Infer number type for known number variables | Type safety for numeric values |
| 2.1.2-UNIT-010 | Unit | P1 | Infer string[] type for known array variables | Type safety for lists |
| 2.1.2-UNIT-011 | Unit | P1 | Default unknown variables to string type | Safe fallback behavior |
| 2.1.2-UNIT-012 | Unit | P1 | Enum variables include correct enum_values | Enum validation support |

**Given-When-Then for P0 tests:**

```gherkin
# 2.1.2-UNIT-007
Given variable name "elicit"
When infer_variable_type is called
Then result.var_type should be Bool
And result.default_value should be false

# 2.1.2-UNIT-008
Given variable name "status"
When infer_variable_type is called
Then result.var_type should be Enum
And result.enum_values should contain ["Draft", "Approved", "InProgress", "Review", "Done"]

# 2.1.2-UNIT-009
Given variable name "epic_num"
When infer_variable_type is called
Then result.var_type should be Number
And result.default_value should be 0
```

**Given-When-Then for P0 tests:**

```gherkin

Given markdown content starting with "---\nvariables:\n  foo:\n    type: number\n---\n# Doc"
```
