## Critical Risks Requiring Immediate Attention

### 1. TECH-001: Template syntax error crashes FUSE handler

**Score: 9 (Critical)**

**Probability:** High - Users will inevitably write malformed Tera syntax. Every typo in `{% for %}` blocks could trigger this.

**Impact:** High - FUSE crash affects ALL file operations, not just the problematic file. Could corrupt filesystem state or leave mount in unusable state.

**Affected Components:**
- `cli/src/fuse.rs` - FuseHandler.read_rendered()
- `sdk/rust/src/graphdocs/renderer.rs` - TemplateProcessor.render()

**Detection Method:** Architecture analysis - no panic handling visible in read path

**Mitigation:**
| Action | Type | Owner | Timeline |
|--------|------|-------|----------|
| Wrap ALL Tera rendering in panic-catching handler | Preventive | Dev | Before alpha |
| Return graceful error content (e.g., `<!-- Render error: line 5 -->`) | Corrective | Dev | Before alpha |
| Never propagate Tera panics to FUSE layer | Preventive | Dev | Before alpha |
| Add circuit breaker for repeated failures on same file | Detective | Dev | Before beta |

**Testing Requirements:**
- Fuzz testing with malformed Tera syntax
- Test all Tera error paths (syntax, runtime, type errors)
- Verify FUSE remains stable after render failure
- Test concurrent access during error recovery

**Residual Risk:** Low - Some edge cases in Tera library may still panic

---

### 2. BUS-001: User confusion between raw/rendered views

**Score: 9 (Critical)**

**Probability:** High - The dual nature (raw vs rendered) is novel and unintuitive. Users will `cat` expecting raw and get rendered, or vice versa.

**Impact:** High - Users may unknowingly commit rendered output to git (if reading rendered and piping to file). Could corrupt documentation workflows. Training/documentation burden.

**Affected Components:**
- User workflows
- Git integration
- Editor integrations

**Detection Method:** UX analysis - no clear visual distinction in rendered output

**Mitigation:**
| Action | Type | Owner | Timeline |
|--------|------|-------|----------|
| Clear documentation with examples | Preventive | PM | Before alpha |
| Add visual indicator in rendered output (first line comment) | Detective | Dev | Before alpha |
| Warning when writing content that looks like rendered output | Detective | Dev | Before beta |
| CLI flag `agentfs cat --raw` as alternative to `.source` | Preventive | Dev | Before beta |

**Testing Requirements:**
- Usability testing with real users
- Verify git workflows work correctly
- Test editor integrations (vim, vscode)
- Test with typical documentation workflows

**Residual Risk:** Medium - Users may still be confused initially

## High Risks

### 3. SEC-001: SQL injection via query() function

**Score: 6 (High)**

**Probability:** Medium - Query strings come from template files, which are user-controlled. String concatenation with `doc_id` is a common pattern shown in examples.

**Impact:** High - Could allow reading arbitrary data from DuckDB, including other documents, secrets, or schema information.

**Mitigation:**
| Action | Type | Owner | Timeline |
|--------|------|-------|----------|
| Parameterized queries where possible | Preventive | Dev | Before alpha |
| Allowlist of permitted SQL operations (SELECT only) | Preventive | Dev | Before alpha |
| Sandbox query execution (read-only transaction) | Preventive | Dev | Before alpha |
| Query result size limits | Detective | Dev | Before beta |

**Testing Requirements:**
- SQL injection test suite (OWASP patterns)
- Test with malicious doc_id values
- Test query() with DROP/UPDATE/DELETE

---

### 4. SEC-002: Arbitrary file read via {% include %}

**Score: 6 (High)**

**Probability:** Medium - Tera's `{% include %}` could be exploited to read files outside the AgentFS mount.

**Impact:** High - Could expose `/etc/passwd`, SSH keys, environment files, or other sensitive data.

**Mitigation:**
| Action | Type | Owner | Timeline |
|--------|------|-------|----------|
| Override Tera's include loader to restrict to AgentFS paths only | Preventive | Dev | Before alpha |
| Validate all include paths are relative and within mount | Preventive | Dev | Before alpha |
| Disable include entirely if not needed | Preventive | Dev | Before alpha |

**Testing Requirements:**
- Test include with `../../../etc/passwd`
- Test include with absolute paths
- Test include with symlinks

---

### 5. DATA-002: Raw template exposed when rendered expected

**Score: 6 (High)**

**Probability:** Medium - Edge cases in `.md` detection, race conditions, or rendering failures could expose raw templates.

**Impact:** High - Exposes internal query structure, potentially sensitive document IDs, and template logic.

**Mitigation:**
| Action | Type | Owner | Timeline |
|--------|------|-------|----------|
| Robust `.md` detection (case-insensitive) | Preventive | Dev | Before alpha |
| Fallback behavior: if render fails, return error not raw | Corrective | Dev | Before alpha |
| Test all edge cases in file extension detection | Detective | Dev | Before beta |

**Testing Requirements:**
- Test with `.MD`, `.Md`, `.markdown` extensions
- Test concurrent read/write scenarios
- Test with symlinks to .md files

---

### 6. TECH-002: Infinite loop in Tera template hangs read

**Score: 6 (High)**

**Probability:** Medium - Complex templates with recursive logic or large loop counts could hang indefinitely.

**Impact:** High - Blocks FUSE read operation, potentially hanging the calling process.

**Mitigation:**
| Action | Type | Owner | Timeline |
|--------|------|-------|----------|
| Render timeout (e.g., 5 seconds max) | Preventive | Dev | Before alpha |
| Loop iteration limit in Tera | Preventive | Dev | Before beta |
| Memory limit for render context | Preventive | Dev | Before beta |

**Testing Requirements:**
- Test with `{% for x in range(1000000) %}`
- Test with recursive macros
- Test timeout behavior

---

### 7. PERF-001: Slow query() blocks FUSE read

**Score: 6 (High)**

**Probability:** High - Users will write expensive queries (full table scans, joins, complex PGQ patterns).

**Impact:** Medium - FUSE read blocks until query completes. Could make file system appear unresponsive.

**Mitigation:**
| Action | Type | Owner | Timeline |
|--------|------|-------|----------|
| Query timeout (e.g., 2 seconds) | Preventive | Dev | Before alpha |
| Query result caching with TTL | Preventive | Dev | Before beta |
| Async query with cancel support | Corrective | Dev | Before GA |

**Testing Requirements:**
- Test with deliberately slow queries
- Test concurrent queries from multiple files
- Test query cancellation

## Medium Risks

### 8. TECH-003: Thread safety issues in TemplateProcessor

**Score: 4 (Medium)**

**Probability:** Medium - Arc<RwLock<Tera>> pattern is correct but easy to misuse.

**Impact:** Medium - Race conditions could cause incorrect rendering or deadlocks.

**Mitigation:**
- Code review by concurrency expert
- Use `parking_lot` instead of std RwLock
- Extensive concurrent testing

---

### 9. PERF-002: Large rendered output causes memory spike

**Score: 4 (Medium)**

**Probability:** Medium - A query returning 10k rows rendered into a table could produce megabytes of output.

**Impact:** Medium - Memory exhaustion, OOM killer, or slow rendering.

**Mitigation:**
- Output size limit (e.g., 1MB max)
- Query result size limit

---

### 10. OPS-001: .source suffix lookup fails silently

**Score: 4 (Medium)**

**Probability:** Medium - Edge cases in FUSE lookup handler could fail to resolve .source suffix correctly.

**Impact:** Medium - User can't access raw template to edit.

**Mitigation:**
- Comprehensive lookup handler testing
- Clear error messages when .source fails

**Score: 3 (Low)**

**Probability:** Low - FUSE read with offset/size is standard pattern.

**Impact:** High - Data corruption would break all file reading.

**Mitigation:**
- Unit tests for offset/size handling
- Integration tests with various read patterns

### 12. OPS-002: Non-.md files accidentally rendered

**Score: 3 (Low)**

**Probability:** Low - Extension check is straightforward.

**Impact:** High - Would break non-markdown files containing `{{` or `{%`.

**Mitigation:**
- Strict extension check (`.md` only)
- Test with files containing Tera-like syntax
