### Core Functionality

Vector Similarity Search (VSS) schema enables semantic file search:
- `fs_embeddings` table stores embedding vectors per inode
- `fs_chunk_embeddings` table stores chunked embeddings for large files
- HNSW index definitions for fast approximate nearest neighbor search
- Model tracking for reproducibility
- Content hash for change detection

## Key Design Decisions

1. **Heavy Integration Focus (61%)**: Vector storage and retrieval are database operations - integration tests against real DuckDB are the appropriate level for validating schema and queries.

2. **P0 for Similarity Search (2.2-E2E-003)**: The core value proposition of VSS is semantic search. Incorrect similarity ranking would defeat the purpose of the entire feature.

3. **P2 for HNSW Index Tests**: HNSW index requires VSS extension which may not be available in all environments. Tests marked P2 to allow graceful degradation.

4. **Content Hash as P0**: Stale embeddings lead to incorrect search results. Change detection is critical for data freshness.

5. **Chunk Embeddings Testing**: Large files require chunking - the composite primary key and offset validation ensure correct reassembly of results.

6. **Test Data with Known Similarity**: Using orthogonal vectors [1,0,0], [0,1,0] and near-parallel vectors [0.9,0.1,0] allows deterministic verification of similarity ranking.
