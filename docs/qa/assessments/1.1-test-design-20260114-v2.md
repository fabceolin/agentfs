**Title:** Schema DDL DuckDB
**Priority:** Critical
**Status:** Ready for Review

### Core Functionality

An append-only journal model for filesystem operations where:
- All operations are immutable events in `fs_journal`
- Current state is derived via `fs_current` view using ROW_NUMBER()
- Binary data stored in `fs_data` with chunking
- Supporting structures: `kv_store`, `tool_calls`, sequences, indexes

### Key Design Principles Tested

1. **Immutability**: No UPDATEs allowed on journal table
2. **State Derivation**: Current state computed via ROW_NUMBER() window function
3. **Time-Travel**: Point-in-time recovery via event_id filtering
4. **Audit Trail**: Complete history preserved for forensics

## QA Risk-Driven Test Scenarios (NEW)

These scenarios address the risk areas identified in the QA review.

### Risk: Concurrent Event Insertion Race Conditions

| ID | Level | Priority | Test | Expected Result | Justification |
|----|-------|----------|------|-----------------|---------------|
| 1.1-CONC-001 | E2E | P0 | 100 concurrent file creates | All inodes unique, no sequence gaps or duplicates | Sequence atomicity under load |
| 1.1-CONC-002 | E2E | P1 | Concurrent updates to same inode | All events recorded, fs_current shows latest | State consistency |
| 1.1-CONC-003 | E2E | P1 | Concurrent deletes and creates | No orphaned state, fs_current accurate | Delete isolation |

**Test Implementation Sketch:**
```python
# 1.1-CONC-001: Concurrent File Creates
import asyncio
import duckdb

async def create_file(conn, session_id):
    inode = conn.execute("SELECT nextval('fs_inode_seq')").fetchone()[0]
    conn.execute("""
        INSERT INTO fs_journal (inode, event_type, parent, name, mode, session_id)
        VALUES (?, 'create', 1, ?, 33188, ?)
    """, [inode, f"file_{session_id}.txt", session_id])
    return inode

async def test_concurrent_creates():
    tasks = [create_file(get_conn(), i) for i in range(100)]
    inodes = await asyncio.gather(*tasks)

    assert len(inodes) == len(set(inodes)), "Duplicate inodes detected!"
    assert max(inodes) - min(inodes) == 99, "Sequence gaps detected!"
```

### Risk: fs_current View Performance Degradation

| ID | Level | Priority | Test | Expected Result | Justification |
|----|-------|----------|------|-----------------|---------------|
| 1.1-PERF-001 | E2E | P0 | Baseline: SELECT * FROM fs_current with 100K events | < 500ms | Performance baseline |
| 1.1-PERF-002 | E2E | P1 | Baseline: directory listing (WHERE parent = N) with 100K events | < 100ms | Index effectiveness |
| 1.1-PERF-003 | E2E | P2 | 1M events performance degradation | Linear or sub-linear growth | Scaling validation |

**Test Implementation Sketch:**
```python
# 1.1-PERF-001: Performance Baseline
import time
import duckdb

def test_fs_current_performance(conn, event_count=100_000):
    # Setup: bulk insert events
    for i in range(event_count):
        conn.execute("""
            INSERT INTO fs_journal (inode, event_type, parent, name, mode, size)
            VALUES (?, 'create', 1, ?, 33188, ?)
        """, [i+2, f"file_{i}.txt", i*100])

    # Measure
    start = time.time()
    result = conn.execute("SELECT * FROM fs_current").fetchall()
    elapsed_ms = (time.time() - start) * 1000

    assert elapsed_ms < 500, f"fs_current took {elapsed_ms}ms (> 500ms threshold)"
    print(f"fs_current with {event_count} events: {elapsed_ms:.1f}ms")
```

**Test Implementation Sketch:**
```python
# 1.1-SEQ-001: Sequence Restart Resilience
def test_sequence_restart():
    # Phase 1: Insert events
    conn1 = duckdb.connect('test.duckdb')
    conn1.execute("LOAD 'schema/duckagentfs.sql'")
    for i in range(10):
        conn1.execute("INSERT INTO fs_journal (...) VALUES (...)")
    max_id = conn1.execute("SELECT MAX(event_id) FROM fs_journal").fetchone()[0]
    conn1.close()

    # Phase 2: Reopen and insert
    conn2 = duckdb.connect('test.duckdb')
    conn2.execute("INSERT INTO fs_journal (...) VALUES (...)")
    new_id = conn2.execute("SELECT MAX(event_id) FROM fs_journal").fetchone()[0]

    assert new_id == max_id + 1, f"Sequence gap: expected {max_id+1}, got {new_id}"
```

```sql
-- Create sequence of events
INSERT INTO fs_journal (inode, event_type, parent, name, mode) VALUES (50, 'create', 1, 'a.txt', 33188); -- event_id 10
INSERT INTO fs_journal (inode, event_type, parent, name, mode) VALUES (51, 'create', 1, 'b.txt', 33188); -- event_id 11
INSERT INTO fs_journal (inode, event_type, parent, name, mode) VALUES (52, 'create', 1, 'c.txt', 33188); -- event_id 12
INSERT INTO fs_journal (inode, event_type, parent, name, mode) VALUES (50, 'delete', 1, 'a.txt', 33188); -- event_id 13

-- Snapshot at event_id 11 (before c.txt, after a.txt and b.txt)
WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY inode ORDER BY event_id DESC) as rn
    FROM fs_journal
    WHERE event_id <= 11 AND event_type != 'delete'
)
SELECT name FROM ranked WHERE rn = 1 AND parent = 1;
-- Expected: 'a.txt', 'b.txt' (NOT 'c.txt')
```
