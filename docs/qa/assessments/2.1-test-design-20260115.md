# Test Design: Story 2.1 - Markdown Parser

Date: 2026-01-15
Designer: Quinn (Test Architect)
Story: STORY-2.1 Markdown Parser
Epic: EPIC-GRAPHDOCS-001

## Test Strategy Overview

- Total test scenarios: 47
- Unit tests: 31 (66%)
- Integration tests: 12 (26%)
- E2E tests: 4 (8%)
- Priority distribution: P0: 23, P1: 16, P2: 8

## Risk Assessment

This story has **elevated complexity** due to:
1. Multiple parsing subsystems (markdown, variables, frontmatter)
2. External ML dependency (TEA Agent library, GGUF model)
3. File system operations (template detection, directory scanning)
4. Embedding-based matching (model2vec, cosine similarity)

**Testing Strategy**: Shift-left with comprehensive unit tests for pure parsing logic, integration tests for component interactions, minimal E2E for critical user journeys.

| ID | Level | Priority | Test Description | Justification |

| 2.1-UNIT-001 | Unit | P0 | Parse H1 heading correctly | Pure parsing logic |

| 2.1-UNIT-005 | Unit | P1 | Extract title from first H1 | Core behavior |
| 2.1-UNIT-006 | Unit | P2 | Handle multiple H1 headings (use first) | Edge case |

**Given-When-Then:**
```
Given: Markdown content "# Hello World\n\n## Section"
When: Parser.parse() is called
Then:
  - sections[0].section_type == Heading
  - sections[0].level == 1
  - sections[0].content == "Hello World"

```

## Recommended Execution Order

1. **P0 Unit tests** (fail fast on core parsing logic)
   - 2.1-UNIT-001 through 2.1-UNIT-010 (sections)
   - 2.1-UNIT-020 through 2.1-UNIT-025 (variables)
   - 2.1-UNIT-026 through 2.1-UNIT-030 (type inference)
   - 2.1-UNIT-037 (edges)
   - 2.1-UNIT-041 through 2.1-UNIT-044 (status normalization)

2. **P0/P1 Integration tests**
   - 2.1-INT-001 through 2.1-INT-008 (component interactions)

3. **P1 Unit tests** (edge cases, secondary features)
   - Remaining unit tests

4. **E2E tests**
   - 2.1-E2E-001 through 2.1-E2E-004

5. **P2 tests** (as time permits)
   - Agent integration tests
   - Edge cases
