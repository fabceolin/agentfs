**3.2-INT-006: Old Symbol Deletion**
```yaml
test_scenario:
  id: '3.2-INT-006'
  requirement: 'AC4'
  priority: P0
  level: integration
  description: 'Verify old symbols are deleted before new symbols are inserted'
  justification: 'Prevents stale symbols after file modification'
  test_sequence:
    - Write file with function "foo"
    - Verify "foo" in code_symbols
    - Modify file to rename "foo" to "bar"
    - Write modified file
    - Verify "foo" NOT in code_symbols
    - Verify "bar" IS in code_symbols
```

1. **P0 Unit tests** (fail fast on core logic)
   - 3.2-UNIT-003, 3.2-UNIT-006, 3.2-UNIT-007, 3.2-UNIT-014, 3.2-UNIT-015

   - 3.2-INT-001, 3.2-INT-003, 3.2-INT-005, 3.2-INT-006

   - 3.2-E2E-001

## Implementation Notes

1. **Test Fixtures**: Create reusable Rust/TypeScript code snippets for consistent testing
2. **Database Setup**: Use in-memory DuckDB for integration tests
3. **tree-sitter Isolation**: Consider mocking tree-sitter for pure unit tests vs. real parsing for integration
4. **CLI Testing**: Use `assert_cmd` crate for CLI E2E tests
5. **Incremental Parsing**: Defer testing until story explicitly requires it
