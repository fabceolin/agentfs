### Core Functionality

An append-only journal model for filesystem operations where:
- All operations are immutable events in `fs_journal`
- Current state is derived via `fs_current` view using ROW_NUMBER()
- Binary data stored in `fs_data` with chunking
- Supporting structures: `kv_store`, `tool_calls`, sequences, indexes

## Key Design Decisions

1. **Heavy Integration Focus (55%)**: Schema DDL is inherently about database structure - unit tests have limited value for schema validation. Integration tests against real DuckDB are the appropriate level.

2. **P0 for State Derivation**: The `fs_current` view is the heart of the append-only model. Incorrect state derivation would corrupt the entire filesystem abstraction.

3. **E2E for Time-Travel**: Time-travel queries require full event history and are best validated with realistic data sequences.

4. **Sequence Testing as P0**: Event ordering depends on sequences. Sequence errors would corrupt audit trails and break time-travel.
