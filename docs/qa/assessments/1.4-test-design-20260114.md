## Test Scenarios by Acceptance Criteria

### AC1: Method `snapshot_at(event_id)` returns read-only filesystem

This is **P0** - data integrity and audit trail capability is critical for compliance/governance use cases.

| ID | Level | Priority | Test Description | Justification |
|----|-------|----------|------------------|---------------|
| 1.4-UNIT-001 | Unit | P0 | Validate event_id parameter bounds (positive integer, within range) | Pure input validation logic |
| 1.4-UNIT-002 | Unit | P0 | Validate error types returned for invalid event_id | Error handling isolation |
| 1.4-INT-001 | Integration | P0 | Create snapshot at valid event_id and verify filesystem structure | DB interaction with fs_journal |
| 1.4-INT-002 | Integration | P0 | Snapshot correctly returns file content at historical point | Multi-component: snapshot + read_file |
| 1.4-INT-003 | Integration | P0 | Snapshot shows deleted files that existed at that event | Critical data recovery scenario |
| 1.4-INT-004 | Integration | P1 | Snapshot reflects file modifications between events | Journal reconstruction correctness |
| 1.4-INT-005 | Integration | P1 | Snapshot at event_id=0 returns empty filesystem | Edge case: empty state |

**Test Scenarios Detail:**

```yaml
test_scenario:
  id: '1.4-UNIT-001'
  requirement: 'AC1'
  priority: P0
  level: unit
  description: 'Validate event_id parameter accepts only positive integers within valid range'
  justification: 'Input validation is pure logic without DB dependency'
  given: 'A DuckAgentFS instance'
  when: 'snapshot_at() is called with various event_id values (-1, 0, MAX_I64+1, NaN)'
  then: 'Appropriate error is returned for invalid inputs'

test_scenario:
  id: '1.4-INT-003'
  requirement: 'AC1'
  priority: P0
  level: integration
  description: 'Snapshot shows deleted files that existed at historical event'
  justification: 'Critical data recovery scenario requiring DB state reconstruction'
  given: 'File created at event 10, deleted at event 20'
  when: 'snapshot_at(15) is called and read_file() is invoked'
  then: 'File content is returned (file existed at event 15)'
```

### AC2: View `fs_current` filters by event_id

This is **P0** - underpins all snapshot queries and audit functionality.

| ID | Level | Priority | Test Description | Justification |
|----|-------|----------|------------------|---------------|
| 1.4-UNIT-003 | Unit | P0 | Query transformation replaces fs_current with fs_current_at correctly | SQL string manipulation logic |
| 1.4-INT-006 | Integration | P0 | Historical view excludes events after snapshot point | Core time-travel correctness |
| 1.4-INT-007 | Integration | P1 | Historical view handles concurrent inode modifications correctly | Window function correctness |

**Test Scenarios Detail:**

```yaml
test_scenario:
  id: '1.4-UNIT-003'
  requirement: 'AC2'
  priority: P0
  level: unit
  description: 'Query rewriter correctly transforms fs_current references to fs_current_at CTE'
  justification: 'SQL transformation is pure string manipulation'
  given: 'A query containing "SELECT * FROM fs_current WHERE parent = 1"'
  when: 'query_current() transforms the query for event_id 100'
  then: 'Query uses fs_current_at CTE with proper WHERE event_id <= 100 filter'

test_scenario:
  id: '1.4-INT-006'
  requirement: 'AC2'
  priority: P0
  level: integration
  description: 'Historical view correctly excludes events after snapshot event_id'
  justification: 'Database integration to verify CTE filtering works end-to-end'
  given: 'Events 1-10 create files A,B; Events 11-20 create files C,D'
  when: 'snapshot_at(10) queries fs_current'
  then: 'Only files A,B are visible; files C,D are not present'
```

### AC3: CLI: `agentfs snapshot <id> --at <event_id>`

This is **P1** - user-facing command for accessing time-travel features.

| ID | Level | Priority | Test Description | Justification |
|----|-------|----------|------------------|---------------|
| 1.4-UNIT-004 | Unit | P1 | CLI argument parsing validates --at flag format | Argument validation logic |
| 1.4-E2E-001 | E2E | P1 | `agentfs snapshot list` displays available events | Complete CLI user journey |
| 1.4-E2E-002 | E2E | P1 | `agentfs snapshot <id> --at <event> cat <path>` reads historical file | Critical user journey |
| 1.4-E2E-003 | E2E | P2 | `agentfs snapshot <id> --at <event> ls <path>` lists historical directory | Secondary user journey |

**Test Scenarios Detail:**

```yaml
test_scenario:
  id: '1.4-E2E-001'
  requirement: 'AC3'
  priority: P1
  level: e2e
  description: 'CLI command agentfs snapshot list displays event timeline'
  justification: 'User-facing CLI requires full environment validation'
  given: 'A DuckAgentFS with 10 recorded events'
  when: 'User runs "agentfs snapshot list my-agent"'
  then: 'Output shows event IDs with timestamps in reverse chronological order'

test_scenario:
  id: '1.4-E2E-002'
  requirement: 'AC3'
  priority: P1
  level: e2e
  description: 'CLI can read file content at specific historical event'
  justification: 'Critical user journey for data recovery use case'
  given: 'File /test.txt with "v1" at event 5, "v2" at event 10'
  when: 'User runs "agentfs snapshot my-agent --at 5 cat /test.txt"'
  then: 'Output shows "v1" (historical content)'
```

### AC5: API to diff between two snapshots

This is **P1** - enables change tracking and audit capabilities.

| ID | Level | Priority | Test Description | Justification |
|----|-------|----------|------------------|---------------|
| 1.4-UNIT-006 | Unit | P0 | ChangeType enum correctly identifies Added/Modified/Deleted/Renamed | Enum logic |
| 1.4-UNIT-007 | Unit | P1 | FileDiff struct correctly populates old_stats and new_stats | Data structure correctness |
| 1.4-UNIT-008 | Unit | P2 | Diff handles rename detection with old_name field | Edge case logic |
| 1.4-INT-010 | Integration | P1 | diff() returns Added for files created in range | Multi-event query |
| 1.4-E2E-004 | E2E | P1 | `agentfs snapshot <id> diff --from <e1> --to <e2>` displays changes | User journey |
| 1.4-E2E-005 | E2E | P2 | Diff output shows correct change types (Added, Modified, Deleted) | Output format validation |
| 1.4-E2E-006 | E2E | P3 | Diff handles large ranges (>1000 events) efficiently | Performance E2E |

**Test Scenarios Detail:**

```yaml
test_scenario:
  id: '1.4-UNIT-006'
  requirement: 'AC5'
  priority: P0
  level: unit
  description: 'ChangeType enum correctly categorizes event types'
  justification: 'Pure enum mapping logic with no DB dependency'
  given: 'Event types: "create", "update", "delete", "rename"'
  when: 'Each event type is mapped to ChangeType'
  then: 'create→Added, update→Modified, delete→Deleted, rename→Renamed'

test_scenario:
  id: '1.4-E2E-004'
  requirement: 'AC5'
  priority: P1
  level: e2e
  description: 'CLI diff command displays changes between two events'
  justification: 'User-facing feature requiring complete system validation'
  given: 'Events 1-10 with creates, updates, and deletes'
  when: 'User runs "agentfs snapshot my-agent diff --from 1 --to 10"'
  then: 'Output lists all changes with file paths and change types'
```

### Read-Only Enforcement (Security)

| ID | Level | Priority | Test Description | Justification |
|----|-------|----------|------------------|---------------|
| 1.4-UNIT-009 (bonus) | Unit | P0 | write_file() on snapshot returns error | Security boundary |
| 1.4-INT-011 (bonus) | Integration | P0 | mkdir(), remove() on snapshot return errors | Security boundary |

```yaml
test_scenario:
  id: '1.4-INT-011'
  requirement: 'AC1 (implicit: read-only)'
  priority: P0
  level: integration
  description: 'All write operations on DuckAgentFSSnapshot return read-only error'
  justification: 'Security boundary test requiring actual method invocation'
  given: 'A snapshot at event 10'
```

## Risk Coverage Matrix

| Risk | Probability | Impact | Test Coverage |
|------|-------------|--------|---------------|
| Data corruption during snapshot query | Low | Critical | 1.4-INT-001, 1.4-INT-002, 1.4-INT-006 |
| Deleted data not recoverable | Medium | High | 1.4-INT-003 |
| Snapshot allows writes (security) | Low | Critical | 1.4-INT-011 |
| Incorrect diff results | Medium | Medium | 1.4-UNIT-006, 1.4-INT-010, 1.4-E2E-004 |
| Performance degradation on large journals | Medium | Medium | 1.4-E2E-006, Implementation Notes |
| CLI parsing errors | Low | Low | 1.4-UNIT-004, 1.4-E2E-001 |

## Recommended Execution Order

1. **P0 Unit tests** (fail fast on logic errors)
   - 1.4-UNIT-001, 1.4-UNIT-002, 1.4-UNIT-003, 1.4-UNIT-006

2. **P0 Integration tests** (core functionality)
   - 1.4-INT-001, 1.4-INT-002, 1.4-INT-003, 1.4-INT-006, 1.4-INT-011

3. **P1 Unit tests**
   - 1.4-UNIT-004, 1.4-UNIT-005, 1.4-UNIT-007

4. **P1 Integration tests**
   - 1.4-INT-004, 1.4-INT-005, 1.4-INT-007, 1.4-INT-008, 1.4-INT-010

5. **P1 E2E tests** (critical user journeys)
   - 1.4-E2E-001, 1.4-E2E-002, 1.4-E2E-004

6. **P2 tests** (if time permits)
   - 1.4-UNIT-008, 1.4-INT-009, 1.4-E2E-003, 1.4-E2E-005

7. **P3 tests** (full regression only)
   - 1.4-E2E-006
