**Reviewer:** Quinn (Test Architect)
**Story:** FUSE Write Handler Not Wired to Handler Registry

**Assessment**: This bug fix carries **elevated risk** due to the critical nature of the FUSE layer modification. The write path is fundamental to filesystem operations, and incorrect implementation could cause data loss or corruption.

---

## Critical Risks Requiring Immediate Attention

### TECH-001: FUSE Write Path Regression

**Score: 9 (Critical)**

| Dimension | Rating | Reasoning |
|-----------|--------|-----------|
| **Probability** | High (3) | FUSE write is heavily used; any bug will manifest immediately |
| **Impact** | High (3) | Data loss, corruption, or silent write failures |

**Description**: Modifying the FUSE `write()` method (used 39 times via `block_on`) risks breaking existing write operations. The write path is the most critical filesystem operation.

**Affected Components**:
- `cli/src/fuse.rs:1395-1447` (write method)
- All file write operations through FUSE mount

**Mitigation Strategy**:
| Type | Actions |
|------|---------|
| **Preventive** | Add handler fallback to `file.pwrite()` when handler returns `None` |
| **Detective** | Run full xfstests suite before merge |
| **Corrective** | Feature flag to disable handler dispatch if issues found |

**Testing Requirements**:
- BUG002-UNIT-005: Handler None falls back to pwrite
- BUG002-INT-007: Existing FUSE mount/read tests pass
- Full xfstests generic/001-100

**Residual Risk**: Medium - Edge cases in concurrent writes may remain

## High Risks

### TECH-002: Path Resolution Race Condition

**Score: 6 (High)**

| Dimension | Rating | Reasoning |
|-----------|--------|-----------|
| **Probability** | Medium (2) | Race conditions are possible but not certain |
| **Impact** | High (3) | Wrong file written, data corruption |

**Description**: The write method needs to resolve inode → path before calling `handle_write`. If the path cache is stale or a rename occurs during write, the wrong file could be modified.

**Affected Components**:
- `cli/src/fuse.rs` - `get_path()` method
- Path cache invalidation logic

**Mitigation**:
- Use inode-based resolution as primary, path as secondary
- Add path validation before handler dispatch
- Test with concurrent rename + write operations

---

### DATA-001: Silent Write Failures

**Score: 6 (High)**

| Dimension | Rating | Reasoning |
|-----------|--------|-----------|
| **Probability** | Medium (2) | Handler errors could be swallowed |
| **Impact** | High (3) | User believes write succeeded when it didn't |

**Description**: If handler dispatch fails and fallback logic is incorrect, writes could fail silently. Users would believe their data was saved when it wasn't.

**Affected Components**:
- Handler registry error propagation
- FUSE reply handling

**Mitigation**:
- Ensure all error paths call `reply.error()`
- Add tracing for all write handler decisions
- Integration test: verify error propagation

---

### PERF-001: Write Latency Regression

**Score: 6 (High)**

| Dimension | Rating | Reasoning |
|-----------|--------|-----------|
| **Probability** | Medium (2) | Additional dispatch overhead |
| **Impact** | High (3) | Noticeable UX degradation on file saves |

**Description**: Adding handler registry dispatch to every write operation introduces overhead. The write path is latency-sensitive (affects editor save, git operations, etc.).

**Affected Components**:
- Every file write through FUSE

**Mitigation**:
- Use fast `can_handle()` check before full dispatch
- Benchmark before/after: target <1ms overhead
- Consider caching handler decisions for hot paths

## Medium Risks

### TECH-003: Handler Priority Ordering

**Score: 4 (Medium)**

| Dimension | Rating | Reasoning |
|-----------|--------|-----------|
| **Probability** | Medium (2) | Multiple handlers could match |
| **Impact** | Medium (2) | Wrong handler processes write |

**Description**: `ConformanceWriteHandler` and `DefaultHandler` both implement `write()`. Incorrect priority ordering could cause the wrong handler to process writes.

**Mitigation**:
- ConformanceWriteHandler priority (25) < DefaultHandler (u32::MAX)
- Unit test priority ordering explicitly

---

### OPS-001: Debugging Complexity

**Score: 4 (Medium)**

| Dimension | Rating | Reasoning |
|-----------|--------|-----------|
| **Probability** | High (3) | FUSE debugging is inherently difficult |
| **Impact** | Low (1) | Slower incident resolution |

**Description**: FUSE operations are hard to debug. Adding handler dispatch layer increases complexity. When writes fail, determining if the issue is in FUSE, handler dispatch, or the handler itself will be challenging.

**Mitigation**:
- Add structured tracing at each decision point
- Log handler name, path, decision, and timing
- Document debugging procedure

---

### TECH-004: Create Handler Not Wired

**Score: 4 (Medium)**

| Dimension | Rating | Reasoning |
|-----------|--------|-----------|
| **Probability** | Medium (2) | `create()` also bypasses handlers |
| **Impact** | Medium (2) | New file conformance may not trigger |

**Description**: The story mentions `create()` (lines 894-944) also bypasses handlers. If only `write()` is fixed, creating new files may not trigger conformance properly.

**Affected Components**:
- `cli/src/fuse.rs:894-944` (create method)

**Mitigation**:
- Consider wiring `handle_create` in same PR
- Or create follow-up story for create handler

---

## Low Risks

### SEC-001: Handler Bypass on Error

**Score: 3 (Low)**

| Dimension | Rating | Reasoning |
|-----------|--------|-----------|
| **Probability** | Low (1) | Requires specific error conditions |
| **Impact** | High (3) | Security-relevant files might bypass validation |

**Description**: If handler dispatch throws an error and fallback writes directly, security-sensitive files could bypass conformance validation.

**Mitigation**:
- On handler error, do NOT fall back - propagate error
- Only fall back on explicit `Ok(None)` (decline to handle)

---

### BUS-001: Feature Incomplete Without Create Fix

**Score: 2 (Low)**

| Dimension | Rating | Reasoning |
|-----------|--------|-----------|
| **Probability** | Medium (2) | Create is used for new files |
| **Impact** | Low (1) | Workaround: edit existing files |

**Description**: If `create()` isn't wired, new files won't trigger conformance. Users must create file first, then edit to trigger conformance.

**Mitigation**:
- Document limitation if create not fixed
- Or include create handler in scope
