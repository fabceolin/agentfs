# Test Design: Story 2.1.1 - Core Markdown Parser

Date: 2026-01-15
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 22
- Unit tests: 16 (73%)
- Integration tests: 6 (27%)
- E2E tests: 0 (0%)
- Priority distribution: P0: 8, P1: 10, P2: 4

## Rationale

The Core Markdown Parser is foundational infrastructure that subsequent stories depend on. It involves:
- Pure parsing logic (unit-testable)
- Data structure transformations (unit-testable)
- No external dependencies (DB, network, filesystem for parsing itself)

E2E tests are deferred to STORY-2.1.3/2.1.4 where full document flows are tested.

## Test Scenarios by Acceptance Criteria

### AC1: Parse headers (H1-H6) as sections

| ID | Level | Priority | Test | Justification |
|----|-------|----------|------|---------------|
| 2.1.1-UNIT-001 | Unit | P0 | Parse H1 header and extract title | Core title extraction, affects all documents |
| 2.1.1-UNIT-002 | Unit | P0 | Parse H2-H6 headers with correct level | Multi-level headings are fundamental |
| 2.1.1-UNIT-003 | Unit | P1 | Preserve header content verbatim | Content integrity is critical |
| 2.1.1-UNIT-004 | Unit | P1 | Handle headers with inline formatting (bold, italic, code) | Common markdown pattern |
| 2.1.1-UNIT-005 | Unit | P2 | Handle empty headers gracefully | Edge case: `# ` with no content |

**Given-When-Then for P0 tests:**

```gherkin
# 2.1.1-UNIT-001
Given a markdown document with "# Project Title" as first line
When the parser processes the document
Then doc.title should equal "Project Title"
And sections[0].section_type should be Heading
And sections[0].level should be 1

# 2.1.1-UNIT-002
Given markdown with headers "## Section" and "### Subsection"
When the parser processes the document
Then sections should contain heading with level 2
And sections should contain heading with level 3
```
