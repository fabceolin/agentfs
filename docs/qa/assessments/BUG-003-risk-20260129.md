## Critical Risks Requiring Immediate Attention

### TECH-001: Race Condition in Multi-Chunk Writes

**Score: 9 (Critical)**

**Probability**: High (3) - Occurs on EVERY file larger than 4KB. 100% reproducible. FUSE sends data in 4KB chunks, and each `write()` call spawns a new conformance task.

**Impact**: High (3) - Multiple consequences:
- Conformance never completes for large files (timeout)
- Multiple Claude API calls wasted (cost + rate limiting)
- Potential `.conformant` file corruption from concurrent writes

**Root Cause**: `cli/src/handler.rs:1303-1315` - The `ConformanceWriteHandler::write()` method spawns a background conformance task on every single write call, rather than waiting for the file to be completely written.

**Mitigation**:
- Move conformance spawn from `write()` to `flush()` handler
- Add `release()` fallback for apps that skip `flush()` (vim, rsync)
- Implement deduplication via `(inode, mtime)` HashMap with 60s TTL cleanup

**Testing Focus**:
- Large file copy (18KB+) - verify single conformance log
- Multiple concurrent file copies
- API call count verification

## High Risks

### OPS-001: API Cost Escalation from Duplicate Calls

**Score: 6 (High)**

**Probability**: High (3) - Every large file triggers multiple API calls
**Impact**: Medium (2) - Cost overrun, potential rate limiting

**Evidence**: An 18KB file results in 5 conformance spawns (18KB / 4KB chunks = 5 writes)

**Mitigation**: Fixed by TECH-001 solution (single spawn via flush)

**Residual Risk**: Low - Post-fix, exactly 1 API call per file

### DATA-001: Potential Data Corruption from Concurrent Writes

**Score: 6 (High)**

**Probability**: Medium (2) - Only occurs when multiple conformance tasks complete simultaneously
**Impact**: High (3) - Corrupted `.conformant` file could break read resolution

**Description**: Multiple conformance processes may attempt to write the `.conformant` output file for the same input file concurrently.

**Mitigation**: Deduplication tracking ensures only one conformance task per file version

**Residual Risk**: Minimal - Dedup prevents concurrent execution

## Medium Risks

None identified.

## Low Risks

### TECH-002: Memory Leak if Dedup Tracking TTL Fails

**Score: 2 (Low)**

**Probability**: Low (1) - TTL cleanup is straightforward to implement
**Impact**: Medium (2) - Gradual memory growth over long sessions

**Mitigation**:
- Use `HashMap::retain()` with 60s TTL
- Cleanup on every `should_process()` check

### OPS-002: Apps That Skip flush() Bypass Conformance

**Score: 2 (Low)**

**Probability**: Medium (2) - vim, rsync, some editors don't call flush()
**Impact**: Low (1) - Conformance triggers on release() fallback

**Mitigation**: `release()` handler serves as fallback trigger
