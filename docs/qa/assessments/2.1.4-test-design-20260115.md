# Test Design: Story 2.1.4 - Agent-Based Transformation

Date: 2026-01-15
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 26
- Unit tests: 10 (38.5%)
- Integration tests: 12 (46%)
- E2E tests: 4 (15.5%)
- Priority distribution: P0: 6, P1: 12, P2: 8

## Rationale

This story involves significant external dependencies:
- TEA binary (subprocess invocation)
- GGUF model file (large external artifact)
- YAML agent definitions (configuration files)

Testing strategy focuses on:
- **Unit tests**: Rule-based fallback logic (no external deps)
- **Integration tests**: TEA subprocess communication (requires TEA)
- **E2E tests**: Full batch transformation workflow

Many tests are marked `#[ignore]` by default since they require TEA + model setup.

## Test Scenarios by Acceptance Criteria

### AC1: Use local YAML agents with GGUF model (gemma3:e4b) to transform non-conforming documents

| ID | Level | Priority | Test | Justification |
|----|-------|----------|------|---------------|
| 2.1.4-UNIT-001 | Unit | P0 | Rule-based transform adds missing sections with TODO placeholders | Fallback mechanism |
| 2.1.4-UNIT-002 | Unit | P0 | Rule-based transform preserves existing section content | Data integrity |
| 2.1.4-UNIT-003 | Unit | P1 | Rule-based transform follows template section order | Structural consistency |
| 2.1.4-UNIT-004 | Unit | P1 | Rule-based transform preserves document title | Data integrity |
| 2.1.4-UNIT-005 | Unit | P2 | Rule-based transform handles empty document | Edge case |

**Given-When-Then for P0 tests:**

```gherkin
# 2.1.4-UNIT-001
Given template with sections ["Status", "Description", "Tasks"]
And document with sections ["Status"] only
And conformance result with missing_sections ["description", "tasks"]
When transform_rule_based is called
Then output should contain "## Description"
And output should contain "<!-- TODO: Add content -->"
And output should contain "## Tasks"

# 2.1.4-UNIT-002
Given document with existing "## Status" containing "Done"
When transform_rule_based is called
Then output should preserve "Done" content under "## Status"
```
